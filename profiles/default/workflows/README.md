# Workflows

Each workflow is a directory here holding `workflow.toml`; plain files such as this one are ignored. The bundled ones start review and address rounds (`review-*`, `address`), nudge whoever someone else's pull request silent for 30 days waits on (`nudge-silent-30d`, which waits for you), close finished or quiet agent sessions (`session-*`), notify you of an answer an agent left unread (`answer-unread`), remove or unregister finished, temporary, duplicate and idle workspaces (`workspace-*`; the removals ship in observe mode, and `workspace-idle-no-pr` waits for you), keep the turn records consistent (`hygiene-*`), close a task you captured and started work on once every unit attached to it has ended (`task-results-ended`), bring a snoozed or muted task back where it was once its wake matches (`task-wake`), give a task someone else owes a check date when no source it links to gives one (`task-check-on`), propose the reply or reaction of an acknowledgment and the redirect of a task that is not yours (`task-acknowledge-*`, `task-not-mine`), and ask you to review the diff once a start turn opens a pull request (`start-review-diff`). A plugin's own workflows live in its profile layer: the Slack plugin's nudges, closures, owner questions and offers to close a task its thread shows done (`slack-*`) are in `plugins/slack/profile/workflows/`. A profile overrides a bundled workflow with a directory of the same name; `workflows.<name>` in the config sets its mode, turns it off or changes its approval.
