# Working on the design system

`design/` is the source of truth for how wloop looks and reads on every surface. A change to a color, a size, a component's guidelines or the information architecture starts here.

## Tokens

`tokens.json` is platform-neutral: lists of named values per family (`color` with its `light` and `dark` themes, `type`, `text`, `spacing`, `radius`, `layout`), and no surface's syntax. Each surface's output is generated from it and never edited by hand:

| Output | Generated by | Guarded by |
|---|---|---|
| The token region of `internal/web/static/app.css` | `go generate ./internal/web` | `TestAppCSSTokensFollowDesign`, `TestAppCSSBreakpointsFollowDesign` |
| `components/bundle.css`, the previews' stylesheet: the cockpit's rules plus `components/preview.css` | `go generate ./internal/web` | `TestDesignBundleFollowsAppCSS` |

Breakpoints stay literal in the media queries, because a media query cannot read a custom property; the test checks each one against a `breakpoint-*` token. Rules that only the previews need (the page's font variables and the *Proposed* components) go in `components/preview.css`.

Every type style's `fontSize` is a step of the `text` scale; `go generate` refuses one that is not.

Future outputs follow the same pattern, a generator and a drift test each: the terminal client's styles, the menu bar's colors and notification badges, and a mobile app's theme.

## The published page

The design system is also published as a claude.ai Design System artifact, made from the files here: `README.md` and the other sections, `tokens.json`, and `components/`. After a change lands, republish the files that changed so the page matches the repository.
