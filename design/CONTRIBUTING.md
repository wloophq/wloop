# Working on the design system

`design/` decides how wloop looks and reads on every surface. The cockpit, the terminal client, the menu bar and the docs follow it: their generated outputs come from it, and their hand-written styles use its tokens and match its styles and component guidelines. When a surface and the design system disagree, the surface is wrong.

## Tokens

`tokens.json` is platform-neutral: lists of named values per family (`color` with its `light` and `dark` themes, `type`, `spacing`, `radius`, `layout`), and no surface's syntax. Each surface's output is generated from it and never edited by hand:

| Output | Generated by | Guarded by |
|---|---|---|
| The token region of `internal/web/static/app.css` | `go generate ./internal/web` | `TestAppCSSTokensFollowDesign`, `TestAppCSSBreakpointsFollowDesign` |
| `components/bundle.css`, the previews' stylesheet: the cockpit's rules plus `components/preview.css` | `go generate ./internal/web` | `TestDesignBundleFollowsAppCSS` |

The text scale comes from the type styles: one `--text-<style>` property per distinct size, named after the first style of that size (`--text-meta` serves `meta`, `age` and `code`). A rule in `app.css` sets a size, weight, family and line height that together match one style.

Breakpoints stay literal in the media queries, because a media query cannot read a custom property; a test checks each one against a `breakpoint-*` token. The cockpit's script reads `--detail-width` from the stylesheet. Rules that only the previews need (the page's font variables and the *Proposed* components) go in `components/preview.css`, built from the same tokens.

## When a drift test fails

Fix the app: regenerate, or change the hand-written rule to follow the design system. Change `design/` only when the change to the design system is the point of the pull request, and say so in it.

Future outputs follow the same pattern, a generator and a drift test each: the terminal client's styles, the menu bar's colors and notification badges, and a mobile app's theme.

## The published page

The design system is also published as a claude.ai Design System artifact, made from the files here: `README.md` and the other sections, `tokens.json`, and `components/`. After a change lands, republish the files that changed so the page matches the repository.
